# DungeonRush2 — "The Sunken Path"

A modern 2D side-scrolling action platformer built in C++17 on SDL2, using the
**Apollo** entity-component-system core.

```
cmake -S . -B cmake-build-debug -DCMAKE_BUILD_TYPE=Release
cmake --build cmake-build-debug -j8
./bin/DungeonRush
```

---

## What this is

A 200×36 tile world (12 800 × 2304 px, 64 px tiles) with a unified scale system,
data-driven level geometry, real hitbox combat, six enemy kinds plus a
three-phase boss, eight powerups, checkpoints, shrines, hazards and a locked
door, over a procedurally drawn parallax backdrop.

The world is **generated**, not hand-placed: `tools/build_level.py` is the single
source of truth for terrain, colliders, spawn points and pickups, and it emits
both the tile maps and the C++ header the game compiles against. Visuals and
physics therefore cannot disagree.

---

## Design rules

Two rules drive the whole rewrite; both exist to kill the "inconsistent size"
problem the predecessor had.

1. **Collider == visual size.** No entity has a per-sprite magic scale number.
   `src/SpriteSpec.h` is the one table pairing art cell size, scale, collider
   size and anchor for every drawable thing. What you see is what collides.
2. **Everything is authored in tile units.** `Level.h` is generated in tiles;
   the game multiplies by `Config::TILE_SIZE`. Nothing is hand-typed in pixels.

## Content

**Enemies (26)** — skeleton ×9, bat ×4, slime ×3, mage ×3, archer ×3, bomber ×3,
boss ×1. Bats fly on a sine path and ignore gravity; slimes hop on a timer;
mages cast bolts; archers telegraph for 0.45 s then snipe from 430 px and
retreat if you close inside 150 px; bombers light a 0.85 s fuse and detonate for
22 damage in a 96 px blast.

**Boss (260 HP)** — three phases. Below 50% it enrages: charges faster, adds a
jump slam that throws two shockwaves along the floor, and fires a 3-bolt
projectile fan every 2.6 s.

**Powerups (11 placements, 8 kinds)** — Health, Speed (×1.6), Invincible,
Double Jump, Damage (×1.5), Magnet (270 px coin pull), Shield (absorbs hits),
CoinX2.

**Facilities (8)** — 3 checkpoints, 3 healing shrines, 1 key, 1 locked door.
**Hazards (6 spike beds)**, **18 platforms** (some moving, some vertical, all
carry the player), **129 coins**.

## Architecture

```
src/
  Config.h              all tuning constants; sizes in tile units
  Level.h               GENERATED by tools/build_level.py — do not hand-edit
  SpriteSpec.h          art cell ↔ collider ↔ anchor, one table for everything
  Game.{h,cpp}          state machine, update order, draw order, HUD, menus
  Map.{h,cpp}           loads the generated tile maps and colliders
  Collision.{h,cpp}     AABB (+ swept ray helpers)
  AssetManager / TextureManager / Vector2D
  main.cpp              window, SDL init, fixed-step loop
  ECS/
    ECS.{h,cpp}         Entity / Component / Manager, bitset groups
    TransformComponent  TransformComponent owns position; see note below
    SpriteComponent, ColliderComponent, TileComponent, HealthComponent,
    HitboxComponent, EnemyAIComponent, ProjectileComponent,
    ParticleComponent, AfterimageComponent, PowerUpComponent,
    MovingPlatformComponent, BobbingComponent, Animation, UILabel
  Systems/
    Systems.{h,cpp}     Physics, Damage, Combat, EnemyAI, Pickup
    Parallax.{h,cpp}    cached sky gradient, sun, clouds, ridges, animated water
    Vfx.{h,cpp}         slash arcs, impact rings, dash afterimages, sparkles
tools/
  build_level.py        the level generator — single source of truth
```

### One thing worth knowing before you touch the physics

`Physics::moveAndCollide` **owns the position** of whatever entity it drives.
`TransformComponent::update()` free-integrates velocity for every *other*
entity, but opts out for physics-driven ones via the `physicsOwnsMotion` flag.

This matters because `Game::update()` runs physics *before* `manager.update()`.
If both integrated, the entity would move twice per frame and — worse — would
begin each physics step already buried inside the floor, so the X-axis pass
would resolve that vertical penetration sideways and fling the actor across the
map. If you add a new moving, colliding entity, route it through
`moveAndCollide` rather than relying on transform integration.

## Level generation

```bash
python3 tools/build_level.py
```

Deterministic (no RNG — pure sine-based terrain), so regenerating reproduces
the same world. It writes:

- `assets/tileset/ForegroundLayer.map` — terrain
- `assets/tileset/DecorLayer.map` — clouds, tufts
- `assets/tileset/CoinLayer.map` — coin mask
- `assets/tileset/Colliders.txt` — terrain rects, derived from the heightmap
- `src/Level.h` — spawn data, platforms, hazards, facilities, powerups, enemies, coins

`GROUND_TOP[col]` is the last *empty* row above the surface, so the surface tile
is `GROUND_TOP + 1` and the water surface is `GROUND_TOP + 4`. `−1` marks a
chasm column (open water top to bottom). Both `tile_for()` in the generator and
`Parallax::drawWater` read it the same way — change one and you must change the other.

## Build

**Dependencies:** SDL2, SDL2_image, SDL2_ttf, SDL2_mixer; CMake ≥ 3.16;
pkg-config; a C++17 compiler.

```bash
# macOS
brew install sdl2 sdl2_image sdl2_ttf sdl2_mixer pkg-config cmake

# Debian / Ubuntu
sudo apt install libsdl2-dev libsdl2-image-dev libsdl2-ttf-dev libsdl2-mixer-dev cmake pkg-config
```

Then either `/bin/bash build.sh` or the CMake commands at the top of this file.
Builds clean under `-Wall -Wextra -Wpedantic` with no warnings.

**Troubleshooting**

- `SDL.h not found` → install SDL2 and check `pkg-config --cflags sdl2`.
- Assets fail to load → the binary uses compile-time `ASSETS_PATH` (absolute
  project path); move the repo and you must re-run CMake.
- No sound → check `assets/sounds/*.wav` and that `Mix_OpenAudio` succeeded.
